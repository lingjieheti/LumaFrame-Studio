# 新制作杜比视界的固定有效画面

宽银幕影片可能在编码画布里嵌入上下黑边，也有左右黑边或四边不等的画面。制作新的 Profile 8.1 动态元数据时，在输出画布上指定左、右、上、下四个像素偏移。软件先在有效区域内检测镜头并测量 MaxRGB，再将同一组四边偏移写入全片的 Level 5。原画布及边框内的影像均保留。完整画幅采用零偏移。已有杜比片源的保留或转换继续使用原片的逐镜 L5。[Dolby 的画幅与亮度分析建议](https://professionalsupport.dolby.com/s/article/Dolby-Vision-Content-Creation-Best-Practices-Guide?language=en_US) · [dovi_tool 2.3.4 的生成配置](https://github.com/quietvoid/dovi_tool/blob/2.3.4/docs/generator.md)

偏移按**输出画布像素**填写。例如将带上下各 138 像素黑边的 1920 × 1080 影片等比放大为 3840 × 2160，对应输出画布的上下边距各为 276 像素。固定设置适用于画幅保持不变的片段。宽银幕与全屏交替的片源，需要为不同画幅分别确定有效区域。默认全幅不会根据一段暗场推测黑边。

```powershell
.\LumaFrameStudio.exe --export 影片.mkv --target newdv --active-area 0 0 276 276 --output 杜比版.mkv --result 核验.json
```

在 RTX 5080 上另取两段共 120 帧的 4K HEVC 画面计时，预热后交替运行完整画幅与四边偏移分析，各取三次中位数。分镜与亮度分析整段由 2.036 秒增至 4.000 秒。指定偏移时，软件使用无分片的 Spline36 在完整画布重建 16 位 RGB，再取精确窗口，使相邻像素的色度滤波连续，也避免奇数边缘错位。该耗时只覆盖分析步骤。

## 验证画面和元数据

用 3840 × 2160、6 帧的原生 10 位 HDR10 测试片，设置左 41、右 74、上 201、下 256 像素的边框，中央填入灰阶渐变，在下边框嵌入一条亮标记。分别通过 1.4.0 正式版和新版的命令行处理，再从两份成片各自提取完整 RPU。表内亮度是最终写入的 12 位 PQ 码值。

| 实际导出 | 四边偏移（左、右、上、下） | L1 最低 | L1 平均 | L1 峰值 | 基础层解码画面 |
|---|---|---:|---:|---:|---|
| 1.4.0 全画幅 | 0 / 0 / 0 / 0 | 0 | 1572 | 4095 | 6/6 帧与输入逐帧 SHA-256 一致 |
| 指定有效画面 | 41 / 74 / 201 / 256 | 12 | 2053 | 2569 | 6/6 帧与输入逐帧 SHA-256 一致 |

旧方式将黑边计入平均亮度，把边框亮标记当作镜头峰值。指定有效画面后，峰值与平均值来自中央渐变。试转入口读回相同结果。所有六帧均带指定的 L5。L1 最低值写为 12 来自 dovi_tool 的 CM 2.9 写入范围约束。[L1 生成处理](https://github.com/quietvoid/dovi_tool/blob/2.3.4/dolby_vision/src/rpu/extension_metadata/blocks/level1.rs#L63-L70)

为检验 4:2:0 上的奇数边距，额外用 192 × 112、带高频色度纹理的 4 帧片段验证左 17、右 22、上 11、下 16 像素的窗口。在完整画布上重建 16 位 PQ RGB，再直接按坐标取像素，得到参考最小、平均、最大 MaxRGB 值 1586、2373、3192。软件分析值为 1586、2372、3191，均相差不超过一个 12 位 PQ 码值。偶数偏移、仅剩一个像素的有效区域及全幅均另行实测。越界或相加后未留下画面的偏移会在导出前提示。成片的 L5、RPU 全文和解码像素分别复读，故意使用错误边距复核时会报告失败。[可执行回归](../tests/test_active_area.py) · [FFmpeg 精确裁幅](https://ffmpeg.org/ffmpeg-filters.html#crop)
