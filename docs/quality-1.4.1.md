# 1.4.1 的片源覆盖与交付验证

## 按输入选择

| 输入与目的 | 桌面选择 | 原画面与元数据 |
|---|---|---|
| 已达目标尺寸的杜比 Profile 7 或 Profile 8.1，保留原作 | 原样保留双层或无损封装 | 保留原始编码画面和杜比元数据 |
| 静态 1080p HDR10，需要 4K HDR10 | 生成 HDR10 → RTX、Spline36 或 FSRCNNX | 直接缩放十位 BT.2020/PQ；有明显压缩痕迹时另可手选 RTX 压缩片源修复 |
| 静态 1080p HDR10，需要 4K 杜比 | 生成杜比视界 → 选择超分模式 | 使用相同的 PQ 超分基础层，按最终画面生成 P8.1 元数据 |
| 已达目标尺寸的静态 HDR10，需要杜比 | 保留 HDR10 原画面 · 生成动态元数据 | 直接复用原始 HEVC 基础层 |
| BT.709 SDR，需要 HDR10 或杜比 | 选目标，再选 203 尼特参考白或高光扩展 | 从 SDR 制作新的 PQ 画面 |

静态 HDR10 输入要求 HEVC Main 10、4:2:0、有限范围 BT.2020/PQ、方形像素及可读的 ST 2086 母版显示信息。应用保留母版显示参数，核对原始帧时间和副轨。已有 Dolby Vision、HDR10+ 和 HDR Vivid 带有不同的元数据，软件在静态 HDR10 路径上检查这些信号。现有 Profile 5、Profile 7 FEL/MEL 和 Profile 8.1 的适用范围见专项说明。[双层与单层处理](profile7.md) · [1.4.0 的保留模式与超分结果](quality-1.4.md)

## 十位 PQ 与成片对照

选用 FelBaker 公开 HDR 测试向量的 4K 基础层，取前 24 帧降至 1920 × 1080，用无损 x265 保留十位 PQ 和原母版显示参数。将交替 40/60 ms 的显示时间、FLAC 音轨和字幕加入输入，以此同时检验非等间隔时间和副轨。1.4.0 会拒绝这个输入，1.4.1 的高码率 RTX、压缩片修复、FSRCNNX 和 Spline36 四条路径均可导出。

每种超分方法分别输出 HDR10 和新制 Dolby Vision，使用 FFmpeg 解码最终 MKV 的完整 3840 × 2160 基础层，逐帧比较 SHA-256。四种方法各有 24/24 帧完全相同。另取同一低清基础层，加入按该视频生成的 Profile 8.1 RPU，作为额外对照。与其输出相比，Spline36 和 FSRCNNX 的采样平均 HDR 色差均为 0；RTX 与压缩片修复分别为 0.486 和 0.595。此处检验两种输入路径的一致性，不能当作相对原始 4K 母版的超分提升。

另制作含黑、约 100、203、1000 尼特的 10 位中性校准条。下表为最终 4K 编码画面内各色条中心 160 × 160 像素的平均亮度码值，再以 ST 2084 换算为尼特。输入已包含十位量化误差。四种方法的暗部与参考白均保持在接近输入的范围，最亮色块的结果略有差异。

| 路径 | 黑 | 约 100 尼特 | 约 203 尼特 | 约 1000 尼特 |
|---|---:|---:|---:|---:|
| 1080p 输入 | 0 | 99.91 | 203.70 | 1004.19 |
| 4K RTX 高码率 | 0 | 99.91 | 203.70 | 1009.46 |
| 4K RTX 压缩片修复 | 0 | 99.91 | 203.70 | 1004.19 |

| 4K FSRCNNX | 0 | 98.78 | 201.49 | 993.73 |

**成片的 MaxCLL 和 MaxFALL。** 对经重新编码的 SDR 或静态 HDR10，软件解码最终 HEVC，对选定的有效区域逐像素计算 MaxRGB 并转换为线性尼特。整部片中的最高像素及最高帧均亮度向上取整，写入 HDR10 内容亮度 SEI。新制 P8.1 同时写入 RPU Level 6。原生 4K HDR10 复制基础层时保留源静态信息。[实测精度和处理时间](content-light-1.4.1.md) · [Dolby 内容亮度说明](https://professionalsupport.dolby.com/s/article/Calculation-of-MaxFALL-and-MaxCLL-metadata)

用独立的双精度 ST 2084 公式对 Spline36 校准条成片的六帧、每帧 8,294,400 个像素重算，得到 1174.912、326.948 尼特。文件中的 MaxCLL、MaxFALL 分别为 1175、327。亮条中心约 1004 尼特；最高像素出现在复杂度更高的条带边缘。另将测量区域先限定在纯黑条内部，再限定在最亮条内部，文件分别写入 0/0 与 1005/1005，六个基础层画面的解码哈希完全一致。全黑测试中的零也符合测量结果。

## 含黑边和剪辑的杜比制作

新生成杜比时可按输出像素指定固定有效区域。已知居中画幅可选 1.85∶1、2.35∶1、2.39∶1 或 4∶3，也可分别填写左、右、上、下边距。编码画布保留不动，软件在有效画面内测量镜头亮度，写入 L5 并从最终 RPU 读回验证。切换片源会恢复完整画幅。宽银幕与全画幅交替的影片需要按各镜头确定边界，全片固定预设不适用。弱切检测增加前后运动与持续亮度检查，已知 16 帧夹具的镜头首帧从 0、12 修正为 0、4、8、12。极弱的暗灰切换仍可能漏检。[有效画幅实测](active-area.md) · [分镜正反例](scene-analysis-1.4.1.md)

```powershell
.\LumaFrameStudio.exe --export 1080p-HDR10.mkv --target hdr10 --mode rtx --output 4K-HDR10.mkv --result hdr.json
.\LumaFrameStudio.exe --export 1080p-HDR10.mkv --target newdv --mode rtx --active-area 0 0 276 276 --output 4K-DV.mkv --result dv.json
```
